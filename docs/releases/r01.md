# Release 1 — Pratos e ingredientes (R01)

**Projeto:** MC-2026 · MainCourse — cardápio, compras e despensa da semana
**Data prevista:** 29/10/2026 (semana S13)
**Tag:** `r01`
**Commit:** `feat(r01): CRUD de pratos e ingredientes + identidade MainCourse`

---

## Resumo

Primeira release de implementação do MainCourse. Entrega os dois cadastros que sustentam o restante
do produto — **pratos** e **ingredientes** — sobre uma base já publicada no GitHub Pages, com banco
Firestore, login anônimo, regras de segurança, tempo real e cache offline.

## Escopo entregue

### Pratos — RFS01 a RFS04

- **RFS01 Incluir prato:** nome obrigatório, 2 a 60 caracteres, sem repetir (maiúsculas/minúsculas
  não diferenciam).
- **RFS02 Consultar prato:** lista em ordem alfabética, busca por parte do nome.
- **RFS03 Alterar prato:** renomear com confirmação de unicidade.
- **RFS04 Excluir prato:** confirmação em diálogo próprio; nesta release não há receitas nem cardápio
  apontando para o prato.

### Ingredientes — RFS05 a RFS08

- **RFS05 Incluir ingrediente:** nome obrigatório, 2 a 60 caracteres, unidade `kg`, `L` ou `un`.
- **RFS06 Consultar ingrediente:** busca por nome e filtro por unidade, em ordem alfabética.
- **RFS07 Alterar ingrediente:** somente a unidade pode mudar; o nome é a chave usada pelas receitas
  e permanece bloqueado na edição.
- **RFS08 Excluir ingrediente:** confirmação em diálogo próprio.

### Base técnica e identidade

- React 19 + TypeScript + Vite, layout responsivo em Tailwind.
- Identidade **MainCourse**: logo, paleta navy/dourado, ícones 32/96/180/192/512, manifest PWA,
  `theme-color` e imagem de compartilhamento.
- Firebase Authentication anônimo + Cloud Firestore com cache persistente.
- Regras do Firestore exigindo autenticação e validando nome/unidade.
- Tela inicial minimalista: apenas “Conectando...”, sem telas de erro para o visitante.
- Deploy no GitHub Pages via GitHub Actions, com `VITE_BASE` calculado pelo nome do repositório.

## Como testar

### Local

```bash
npm install
cp .env.example .env.local   # preencha com as chaves do Firebase
npm run dev
```

1. Cadastre um prato e confira a mensagem de sucesso.
2. Tente cadastrar o mesmo nome com outra caixa (`Lasanha` / `lasanha`) — deve recusar.
3. Renomeie o prato e confira a lista.
4. Exclua e confirme no diálogo.
5. Repita para ingredientes, testando as unidades `kg`, `L` e `un`.
6. Edite um ingrediente: o nome fica bloqueado e só a unidade muda.
7. Use os filtros de nome e unidade.
8. Recarregue a página: os dados continuam lá (Firestore + cache).
9. Desligue a internet e recarregue: o cache local mantém a lista (modo offline do Firestore).
10. Rode a suíte Selenium (com o app local ou a URL do Pages):

```bash
pip install -r tests/selenium/requirements.txt
BASE_URL=http://localhost:5173/ pytest tests/selenium
```

### Publicado

Acesse a URL do Pages, faça um cadastro e confira em **Firestore → Dados** se o documento apareceu.
Depois abra em outro navegador/dispositivo e veja a atualização em tempo real.

## Decisões técnicas

- **O nome é o id do documento**, normalizado para minúsculas. Isso garante a unicidade
  case-insensitive exigida pelo DRE sem uma consulta extra. O nome exibido preserva a grafia do
  usuário.
- **Renomear é apagar + criar** em um `writeBatch`. Na R02, o mesmo fluxo passa a atualizar as
  receitas e o cardápio que referenciam o prato.
- **Ingrediente não muda de nome** (RFS07); a edição altera apenas `unidade_medida`.
- **A sessão anônima é aguardada antes das leituras** (`authStateReady`), evitando
  `permission-denied` na primeira renderização.
- **A build não falha sem as chaves**: o app permanece em “Conectando...” e o erro técnico vai para
  o console, sem expor mensagens de infraestrutura na interface.

## Limitações conhecidas

- Não há receitas, despensa, cardápio nem lista de compras nesta release.
- A exclusão de prato ainda não precisa bloquear dias do cardápio (a entidade não existe na R01).
- O login é anônimo e aberto a quem tem a URL; as regras impedem acesso sem sessão, mas não
  distinguem moradores. Para o escopo acadêmico, a URL é restrita.
- Os testes E2E gravam e apagam registros reais; use uma base de testes ou a URL de homologação.
